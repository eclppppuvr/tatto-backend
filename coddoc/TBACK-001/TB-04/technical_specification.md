## 1. Обзор изменения

### 1.1. Что делаем и тип изменения
**Суть:** Пользователь вводит текстовое описание желаемой татуировки и выбирает стиль (из фиксированного набора или вводит свой). Система асинхронно генерирует уникальный тату-дизайн через AI-пайплайн (Yandex AI Studio / AliceAI). Результат — готовый эскиз на белом фоне в MongoDB. Пользователь видит прогресс через WebSocket с fallback на polling.

**Тип:** новый функционал
**Стороны:** Fullstack

### 1.2. Затронутые сервисы и владельцы

| Сервис | Роль в задаче | Владелец/команда | Происхождение |
|--------|---------------|------------------|---------------|
| API (tatto-backend) | Новый сервис, владелец всех взаимодействий | Команда проекта | 🟢 |
| Celery worker | Асинхронная обработка AI-пайплайна | Команда проекта | 🟢 |
| S3 (MinIO) | Хранение результирующих изображений | Команда проекта | 🟢 |
| PostgreSQL | Хранение Jobs (статус, прогресс) | Команда проекта | 🟢 |
| MongoDB | Хранение эскизов (sketches) | Команда проекта | 🟢 |
| Redis | Broker для Celery | Команда проекта | 🟢 |

### 1.3. Связь с бизнес-требованиями
Реализует FR-2 из БТ: пользователь вводит текстовое описание и выбирает стиль, получает готовый эскиз за < 120 секунд.

## 2. Взаимодействия (ядро)

### INT-1. Отправка запроса на генерацию — 🟢
- **Вид:** новое
- **Граница/направление:** FE → BE
- **Триггер:** пользователь вводит описание и нажимает «Сгенерировать»
- **Контракт (запрос):** `POST /v1/generation`
  - Authorization: `Bearer <access_token>`
  - `prompt` (string, required, max 500) — текстовое описание желаемой татуировки
  - `style` (enum, required) — стиль: `minimalism`, `old_school`, `realism`, `geometry`, `japanese`, `custom`
  - `custom_style` (string, optional, max 100) — если style=custom, пользовательское описание стиля
- **Контракт (ответ):** `202 Accepted`
  - `job_id` (UUID) — ID задачи
  - `status` (enum: `pending`) — начальный статус
- **Пример запроса:**
  ```json
  {
    "prompt": "Морской компас с якорем",
    "style": "old_school"
  }
  ```
- **Пример ответа (успех):**
  ```json
  {
    "job_id": "j1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "status": "pending"
  }
  ```
- **Ошибки:**
  - `400 Bad Request` — «prompt обязателен»
  - `422 Unprocessable` — «style не в enum'е» / «prompt более 500 символов»
  - `401 Unauthorized` — «Неавторизован»
- **Состояния UI по ответу:** значение → показать job_id, переключиться на экран прогресса; ошибка → показать сообщение
- **Авторизация:** JWT required
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-2

### INT-2. Получение статуса Job — 🟢
- **Вид:** новое (дублирует INT-2 из TB-03, но для generate_design type)
- **Граница/направление:** FE → BE
- **Триггер:** polling (каждые 5 сек) или WebSocket disconnect
- **Контракт (запрос):** `GET /v1/jobs/{job_id}`
  - Authorization: `Bearer <access_token>`
- **Контракт (ответ):** `200 OK`
  - `id` (UUID)
  - `status` (enum: `pending`, `running`, `done`, `failed`, `cancelled`)
  - `progress` (integer, 0–100) — текущий прогресс
  - `output_ref` (string | null) — S3-ключ или MongoDB _id результата
  - `error_code` (string | null) — машинный код ошибки
  - `error_message` (string | null) — человекочитаемое описание ошибки
  - `created_at` (ISO 8601)
  - `finished_at` (ISO 8601 | null)
- **Пример ответа (done):**
  ```json
  {
    "id": "j1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "status": "done",
    "progress": 100,
    "output_ref": "sk_a1b2c3d4e5f6",
    "error_code": null,
    "error_message": null,
    "created_at": "2026-10-31T10:00:00Z",
    "finished_at": "2026-10-31T10:01:00Z"
  }
  ```
- **Ошибки:**
  - `401 Unauthorized` — «Токен недействителен»
  - `403 Forbidden` — «Job не принадлежит пользователю»
  - `404 Not Found` — «Job не найден»
- **Состояния UI по ответу:** `pending` → спиннер; `running` → прогресс-бар; `done` → показать результат; `failed` → показать ошибку + кнопку «Повторить»
- **Авторизация:** JWT required
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-2

### INT-3. WebSocket: получение прогресса — 🟢
- **Вид:** новое (дублирует INT-3 из TB-03)
- **Граница/направление:** FE ↔ BE
- **Триггер:** подключение клиента к WebSocket-каналу
- **Контракт (подключение):** `WS /v1/ws/jobs/{job_id}`
  - Подключается с JWT в query-параметре: `?token=<access_token>`
- **Контракт (сообщение от сервера):** JSON
  - `type` (enum: `progress`, `done`, `error`)
  - `job_id` (UUID)
  - `progress` (integer, 0–100)
  - `status` (enum: `pending`, `running`, `done`, `failed`)
  - `message` (string | null)
- **Пример сообщения (done):**
  ```json
  {
    "type": "done",
    "job_id": "j1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "progress": 100,
    "status": "done",
    "message": null
  }
  ```
- **Ошибки подключения:**
  - `401 Unauthorized` — токен недействителен
  - `404 Not Found` — job не найден
- **Состояния UI по ответу:** `progress` → обновить прогресс-бар; `done` → показать результат; `error` → показать ошибку
- **Авторизация:** JWT в query-параметре
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-2

### INT-4. Получение результата генерации — 🟢
- **Вид:** новое (дублирует INT-4 из TB-03, но для source=generation)
- **Граница/направление:** FE → BE
- **Триггер:** пользователь открывает результат генерации
- **Контракт (запрос):** `GET /v1/sketches/{sketch_id}`
  - Authorization: `Bearer <access_token>`
- **Контракт (ответ):** `200 OK`
  - `id` (string, MongoDB ObjectId)
  - `user_id` (UUID)
  - `source` (enum: `extract`, `generation`)
  - `prompt` (string) — промпт генерации
  - `style` (enum: `minimalism`, `old_school`, `realism`, `geometry`, `japanese`, `custom`)
  - `custom_style` (string | null) — пользовательский стиль
  - `status` (enum: `active`, `deleted`)
  - `s3` (object) — `result_png`, `thumbnail`
  - `meta` (object) — `width`, `height`, `model`, `seed`, `steps`, `latency_ms`
  - `created_at` (ISO 8601)
- **Пример ответа (успех):**
  ```json
  {
    "id": "sk_a1b2c3d4e5f6",
    "user_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "source": "generation",
    "prompt": "Морской компас с якорем",
    "style": "old_school",
    "custom_style": null,
    "status": "active",
    "s3": {
      "result_png": "sketches/sk_a1b2c3d4e5f6.png",
      "thumbnail": "sketches/sk_a1b2c3d4e5f6_thumb.jpg"
    },
    "meta": {
      "width": 1024,
      "height": 1024,
      "model": "stub-generator",
      "seed": 42,
      "steps": 30,
      "latency_ms": 35000
    },
    "created_at": "2026-10-31T10:01:00Z"
  }
  ```
- **Ошибки:**
  - `401 Unauthorized` — «Токен недействителен»
  - `403 Forbidden` — «Эскиз не принадлежит пользователю»
  - `404 Not Found` — «Эскиз не найден или удалён»
- **Состояния UI по ответу:** значение → показать эскиз; ошибка → «Эскиз не найден»
- **Авторизация:** JWT required
- **Происхождение:** 🟢 новое
- **Трассировка:** FR-2

### Каталог ошибок (сводно)

| Код | Тело/сообщение | Когда | Состояние UI |
|-----|----------------|-------|--------------|
| 400 | «Некорректный запрос» | prompt пуст / style не в enum | Показать ошибку валидации |
| 401 | «Неавторизован» | Токен недействителен | Редирект на логин |
| 403 | «Доступ запрещён» | Job/эскиз не принадлежит пользователю | Показать «нет доступа» |
| 404 | «Не найдено» | Job/эскиз не существует | Показать «не найдено» |

| 500 | «Внутренняя ошибка сервера» | Неожиданная ошибка | «Сервис временно недоступен» |
| 504 | «Таймаут обработки» | AI-модель > 120 сек | Показать ошибку + «Повторить» |

## 3. Backend — ответственность

### 3.1. По сервисам

**API (tatto-backend)** — реализует INT-1, INT-2, INT-4.

- INT-1 (generation request): валидация prompt и style, создание Job в PostgreSQL со статусом `pending`, публикация события в Redis для Celery, возврат `job_id`
- INT-2 (job status): чтение Job из PostgreSQL, проверка ownership
- INT-4 (sketch detail): чтение эскиза из MongoDB, проверка ownership

**Celery worker** — обработка AI-пайплайна.

- Подписка на очередь `cpu` (Celery + Redis broker)
- Забирает задачу из очереди, обновляет Job на `running`, публикует прогресс в Redis pub/sub
- Вызывает AIEngine.generate_design() (Yandex AI Studio / AliceAI, 5 стилей: minimalism, old_school, realism, geometry, japanese + custom)
- Сохраняет результат в S3 (`sketches/{uuid}.png`), создаёт документ в MongoDB (sketches, source=generation)
- Обновляет Job на `done` (или `failed` при ошибке)

**S3 (MinIO)** — хранение изображений.

- Bucket `tattoo`, префикс `sketches/`
- Ключи иммутабельны

**PostgreSQL** — хранение Jobs.

- Таблица `jobs`: type=`generate_design` (ENUM), статусы и прогресс как в TB-03

**MongoDB** — хранение эскизов.

- Коллекция `sketches`: source=`generation`, дополнительные поля: `prompt`, `style`, `custom_style`, `meta.seed`, `meta.steps`

**Redis** — broker для Celery.

- Broker для Celery: `redis://:password@localhost:6379/0`
- Pub/sub каналы: `job:channel:{job_id}`

### 3.2. Данные и хранение

- 🟢 `jobs` (PostgreSQL) — таблица: `type` (ENUM: `extract_sketch`, `generate_design`, `try_on`), для генерации: `input_ref` = промпт + стиль (TEXT), `output_ref` = MongoDB _id
- 🟢 `sketches` (MongoDB) — коллекция: `source` (ENUM: `extract`, `generation`), `prompt` (string), `style` (ENUM: `minimalism`, `old_school`, `realism`, `geometry`, `japanese`, `custom`), `custom_style` (string, nullable), `s3.result_png`, `s3.thumbnail`, `meta.seed` (long), `meta.steps` (int), `meta.model` (string), `meta.latency_ms` (int)
- Индексы MongoDB: `{user_id: 1, created_at: -1}`, `{user_id: 1, source: 1}`, `{tags: 1}`, `{meta.model: 1}`
- Миграции: нет (таблицы создаются в TB-03)

### 3.3. Авторизация/доступ на бэке

- INT-1, INT-2, INT-4 требуют JWT в заголовке `Authorization: Bearer <token>`
- Валидация: проверка подписи JWT, срока действия
- INT-2, INT-4: проверка ownership (user_id из JWT)
- INT-3 (WebSocket): JWT в query-параметре

## 4. Frontend — ответственность

### 4.1. Где и что меняется в UI

- Экран генерации: поле ввода prompt (textarea, max 500 символов), выбор стиля (radio buttons: минимализм, олд-скул, реализм, геометрия, японский + поле «другой стиль»), кнопка «Сгенерировать»
- Экран прогресса: job_id, прогресс-бар, статус обработки
- Экран результата: превью эскиза, промпт и стиль под эскизом, кнопки «Скачать», «Примерить»

### 4.2. Пользовательские сценарии

**Основной поток (FR-2):**
1. Пользователь открывает экран «Генерация»
2. Вводит промпт, выбирает стиль → нажимает «Сгенерировать» → INT-1
3. Получает job_id → переключается на экран прогресса
4. Подключается к WebSocket → получает прогресс в реальном времени
5. При `status=done` → INT-4 → показывает результат

**Ветвление (polling fallback):**
1. WebSocket не подключился → polling каждые 5 секунд → INT-2
2. При `status=done` → INT-4 → показывает результат

**Ветвление (ошибка обработки):**
1. AI-обработка завершилась ошибкой → WS отправляет `type=error` или polling возвращает `status=failed`
2. Фронт показывает ошибку + кнопку «Повторить»

### 4.3. Состояния (именованные)

| Имя состояния | Условие | Что видит пользователь |
|---------------|---------|------------------------|
| `idle` | До отправки запроса | Форма ввода промпта и выбора стиля |
| `submitting` | Отправка POST /v1/generation | Спиннер «Отправка...» |
| `pending` | Job создан, обработка не началась | «Задача в очереди...» |
| `processing` | Job running, progress < 100 | Прогресс-бар с процентом |
| `done` | Job done, status=done | Превью эскиза, кнопки «Скачать», «Примерить» |
| `error` | Job failed, status=failed | Сообщение об ошибке + кнопка «Повторить» |
| `error_network` | WS disconnect + polling не отвечает | «Соединение потеряно» + кнопка «Повторить» |

### 4.3.1. Loading и таймауты

- **Таймаут отправки запроса:** 10 секунд
- **Таймаут polling:** 10 секунд
- **Polling интервал:** 5 секунд (если WS недоступен)
- **Hard-limit AI-обработки:** 120 секунд (согласно БТ)
- При таймауте → состояние `error_network` + кнопка «Повторить»

### 4.4. Доступ по ролям в UI

- `client`, `master`, `admin`: полный доступ к генерации

## 5. Нефункциональные требования

### 5.1. Синхронность, кэш, производительность

- INT-1: синхронный ответ (202 Accepted), обработка асинхронная
- INT-2: синхронный запрос к PostgreSQL
- INT-3: WebSocket, Redis pub/sub
- AI-пайплайн (Yandex AI): ~5–30 секунд на MVP (зависит от стиля и сложности промпта)
- Очередь Celery: `cpu` (для extract и generation)
- Retry: max 3 попытки, exponential backoff (10s, 30s, 90s)
- **Кэш: нет** (по решению аналитика, генерируем заново каждый раз)

### 5.2. Надёжность/деградация

- При недоступности S3: API возвращает 503, фронт показывает «хранилище временно недоступен»
- При недоступности Redis: Celery не может забирать задачи
- При недоступности MongoDB: результат сохраняется в S3, но MongoDB не обновляется — ошибка логируется
- Job при `failed` с `retry_count < 3` автоматически перезапускается воркером

### 5.3. Безопасность/доступ (сводно)

- JWT-авторизация на всех эндпоинтах
- Валидация prompt: max 500 символов, sanitize от XSS
- S3-ключи иммутабельны
- Ownership-проверка на INT-2, INT-4

## 6. Релиз и интеграция

### 6.1. Порядок выката

1. BE: миграции БД (нет), API-эндпоинты (INT-1, INT-2, INT-4)
2. Workers: Celery-воркер с AIEngine.generate_design() (Yandex AI Studio / AliceAI)
3. FE: интеграция с новыми эндпоинтами + WebSocket

BE и workers деплоятся одновременно, FE — после.

### 6.2. Обратная совместимость

- На данном этапе нет существующих потребителей — обратная совместимость не применима
- Все эндпоинты версионируются (`/v1/...`)

### 6.3. Фиче-флаги

Не применимо: задача не использует фиче-флаги

### 6.4. План отката

- **Откат только BE:** API перестаёт создавать jobs для генерации, старые jobs остаются в `pending`/`running`. FE на старой версии не вызывает новые эндпоинты — безопасно.
- **Откат только FE:** BE отдаёт новые эндпоинты, FE игнорирует — безопасно.
- **Откат workers:** jobs остаются `running` indefinitely — FE показывает прогресс-бар, но не получает финальный статус.

### 6.5. Преднастройка до релиза (чек-лист)

- [ ] Роли в security-сервисе — роли `client`, `master`, `admin` (из TB-02)
- [ ] DDL-миграция в репо владеющего сервиса — нет (таблицы из TB-03)
- [ ] Конфиги по окружениям (dev/staging/prod) — S3_URL, REDIS_URL, CELERY_BROKER_URL, AI_ENGINE=yandex
- [ ] Сервисные аккаунты для межсервисных вызовов — не требуется
- [x] Фиче-флаги заведены — не требуются

## 7. Трассировка приёмки

| FR из БТ | Взаимодействие(я) | Тест-кейс (Дано–Когда–Тогда) |
|----------|-------------------|-------------------------------|
