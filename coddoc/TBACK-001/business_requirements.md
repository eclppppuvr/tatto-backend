## 1. Введение и контекст

### 1.0. Тип изменения
Новый функционал

### 1.1. Описание проблемы
Тату-мастерам и клиентам не хватает инструмента для быстрого создания профессиональных эскизов татуировок. Мастеру приходится тратить часы на поиск похожих эскизов в интернете или рисование с нуля. Клиент не может визуализировать, как будет выглядеть татуировка на конкретном участке тела, что приводит к разочарованиям после сеанса.

### 1.2. Конечные потребители
- Тату-мастера — для быстрого поиска референсов, создания эскизов по запросу клиента и демонстрации вариантов перед сеансом
- Клиенты тату-салонов — для визуализации будущей татуировки, подбора стиля и места нанесения до похода к мастеру
- Любители татуировок — для генерации идей, вдохновения и экспериментов с дизайнами

## 2. Бизнес-требования (цели и ценность)

### 2.1. Бизнес-цель
Я как тату-мастер или клиент должен иметь возможность загрузить фото татуировки на теле, сгенерировать эскиз по текстовому описанию и примерить эскиз на тело, чтобы сэкономить время на поиск референсов и визуализировать результат до сеанса.

### 2.2. Ценность для бизнеса
- **Экономия времени** — мастеру не нужно тратить часы на поиск похожих эскизов в интернете или рисование с нуля
- **Визуализация перед принятием решения** — клиент видит, как будет выглядеть татуировка на конкретном участке тела, избегая разочарований
- **Доступность** — любой человек без навыков рисования может создать профессиональный эскиз и прийти к мастеру с четким техническим заданием
- **Интерактивность и вдохновение** — генерация множества вариантов для выбора лучшего дизайна

### 2.3. Бизнес-риски и меры по снижению

| Риск | Вероятность / влияние | Меры по снижению |
|------|-----------------------|------------------|
| Низкое качество AI-моделей (точность извлечения < 70%) | Высокая / высокое | Прототипирование моделей на раннем этапе, запас времени на дообучение |
| Превышение лимита 120 сек на генерацию | Средняя / высокое | Оптимизация пайплайна, кэширование результатов, асинхронная обработка |
| Зависимость от внешних AI-API (оплата, доступ, аптайм) | Средняя / среднее | Использование локальных моделей (OpenCV, SAM) + fallback на API |
| Ограниченные ресурсы команды (учебный проект, 5 человек) | Высокая / среднее | Приоритизация MVP, stub AI-модели для параллельной разработки |
| Объём хранимых изображений | Средняя / низкое | Версионирование S3, удаление временных файлов, компрессия |

## 3. Объём проекта

### 3.1. Входит в проект
- Модуль для загрузки фото и AI-обработки (извлечение татуировки, дорисовка, перевод на белый фон)
- Модуль генерации эскизов по текстовому запросу с выбором стилей (минимализм, олд-скул, реализм, геометрия, японский и др.)
- Модуль виртуальной примерки с возможностью наложения эскиза на различные части тела
- Личный кабинет пользователя с историей созданных эскизов
- База данных для хранения эскизов, пользовательских настроек и фото манекенов

### 3.2. Не входит в проект
- Реальная татуировка на теле (только визуализация)
- Печать эскизов на бумаге или трафаретах
- Интеграция с платёжными системами
- Мобильное приложение (только веб-приложение)

### 3.3. Архитектурные изменения и интеграции
- Веб-приложение с клиент-серверной архитектурой (микросервисы или монолит для MVP)
- Использование AI-моделей для обработки изображений (OpenCV, модели сегментации, генеративные API)
- Развёртывание через Docker

### 3.4. Внешние зависимости
Внешних зависимостей нет — весь бэкенд разрабатывается командой проекта.

## 4. Функциональные требования

### 4.1. Описание функционала / бизнес-процесса

**FR-1. Считывание эскиза с фотографии (Image-to-Tattoo)**
Пользователь загружает фото татуировки на теле → система извлекает татуировку, дорисовывает недостающие элементы, переводит на белый фон без перспективы и телесных искажений → пользователь получает готовый эскиз на белом фоне, пригодный для трафаретной печати.

**FR-2. Генерация эскиза по текстовому описанию (Text-to-Sketch)**
Пользователь вводит текстовое описание желаемой татуировки и выбирает стиль (минимализм, олд-скул, реализм, геометрия, японский и др.) → система генерирует уникальный тату-дизайн → пользователь получает готовый эскиз на белом фоне.

**FR-3. Примерка эскиза на тело (Try-On)**
Пользователь выбирает существующий эскиз и фотографию тела (или виртуального манекена) → система накладывает эскиз на выбранную часть тела с учётом анатомических изгибов → пользователь видит реалистичную визуализацию будущей татуировки.

**FR-4. Личный кабинет пользователя**
Пользователь регистрируется и входит в систему → получает доступ к истории созданных эскизов, настройкам профиля, управлению загруженными фото.

### 4.2. Критерии приёмки

- **[FR-1]** Дано пользователь загрузил фото татуировки на теле, когда система обработала изображение, тогда пользователь получает эскиз на белом фоне с точностью извлечения не менее 70% (по субъективной оценке пользователей).
- **[FR-2]** Дано пользователь ввёл текстовое описание и выбрал стиль, когда система сгенерировала эскиз, тогда пользователь получает готовый эскиз за < 120 секунд с момента отправки запроса.
- **[FR-3]** Дано пользователь выбрал эскиз и фото тела, когда система обработала изображение, тогда пользователь видит наложение эскиза на выбранную часть тела с корректным учётом анатомических изгибов.
- **[FR-4]** Дано пользователь зарегистрировался и вошёл в систему, когда пользователь открыл личный кабинет, тогда пользователь видит историю всех созданных эскизов и может управлять настройками профиля.
